## 🚀 Запуск серверной части (Node.js)

### 1. Установка зависимостей

```bash
cd C:\Users\tahgancrazy\Documents\GitHub\ket-hr-frontend\hr-demo\backend
npm install
```

### 2. Настройка окружения

Создайте файл `.env` в папке `backend`:

```env
PORT=5000
DB_HOST=localhost
DB_PORT=3306
DB_USER=root
DB_PASSWORD=
DB_NAME=i91590fx_db
JWT_SECRET=supersecretkey
```

### 3. Запуск сервера

```bash
npm run dev
```

Сервер запустится на `http://localhost:5000`

## 🔐 Получение JWT-токена (логин)

### Тестовые учетные записи

| Логин (username) | Пароль | Роль |
|------------------|--------|------|
| admin | admin123 | admin |
| petrova_a | admin123 | admin |
| smirnova_m | admin123 | hr |
| ivanov_i | admin123 | employee |
| kozlov_a | admin123 | employee |

### Запрос на получение токена

```bash
curl -X POST http://localhost:5000/api/auth/login \
  -H "Content-Type: application/json" \
  -d "{\"username\":\"admin\",\"password\":\"admin123\"}"
```

### Пример ответа

```json
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "user": {
    "id": 10,
    "username": "admin",
    "email": "admin@company.ru",
    "role": "admin"
  }
}
```

> ⚠️ **Важно:** Сохраните полученный токен — он понадобится для всех защищённых API-запросов.

## 🧪 Тестирование API

### Пример запроса к защищённому эндпоинту

```bash
curl http://localhost:5000/api/departments \
  -H "Authorization: Bearer ВАШ_ТОКЕН_СЮДА"
```

### Основные эндпоинты API

| Метод | Эндпоинт | Описание | Доступ |
|-------|----------|----------|--------|
| POST | `/api/auth/login` | Авторизация | публичный |
| GET | `/api/departments` | Список отделов | все авторизованные |
| GET | `/api/employees` | Список сотрудников | все авторизованные |
| GET | `/api/employees/:id` | Карточка сотрудника | все авторизованные |
| POST | `/api/employees` | Добавление сотрудника | hr, admin |
| PUT | `/api/employees/:id` | Обновление сотрудника | hr, admin |
| DELETE | `/api/employees/:id` | Увольнение (is_active=false) | hr, admin |
| GET | `/api/candidates` | Список кандидатов | hr, admin |
| POST | `/api/candidates` | Добавление кандидата | hr, admin |
| GET | `/api/vacancies` | Список вакансий | все авторизованные |
| GET | `/api/vacations` | Отпуска сотрудников | hr, admin, employee (свои) |
| POST | `/api/vacations` | Создание заявки на отпуск | все авторизованные |

## 🧪 Чек-лист для ручного тестирования

### Позитивные тесты

- [ ] Логин с валидными admin/admin123 → получаем токен (200)
- [ ] GET `/api/departments` с валидным токеном → статус 200, массив отделов
- [ ] GET `/api/employees` с токеном admin → статус 200, список сотрудников
- [ ] POST `/api/employees` с токеном admin → статус 201, создание сотрудника
- [ ] GET `/api/employees/:id` с существующим ID → статус 200, данные сотрудника
- [ ] GET `/api/candidates` с токеном hr → статус 200

### Негативные тесты

- [ ] Логин с неверным паролем → статус 401, сообщение об ошибке
- [ ] Логин с несуществующим пользователем → статус 401
- [ ] GET `/api/employees` без токена → статус 401
- [ ] GET `/api/employees` с просроченным токеном → статус 403
- [ ] GET `/api/employees/:id` с несуществующим ID → статус 404
- [ ] GET `/api/candidates` с токеном employee (нет прав) → статус 403
- [ ] POST `/api/employees` с токеном employee (нет прав) → статус 403

### Тесты валидации

- [ ] POST `/api/employees` с пустым first_name → статус 400
- [ ] POST `/api/employees` с некорректным email → статус 400

## 📝 Примечания для backend-разработки

### Безопасность

- **Хеширование паролей:** bcrypt (10 раундов соли)
- **JWT-токен:** время жизни — 24 часа
- **Защита от брутфорса:** rate limiting (100 запросов/15 минут)
- **Пароль admin123** захеширован через bcrypt в БД
